## 定位

从上游 TalkifyTTS 1.0.37（commit `95b5187`）拉出的独立分支，目标是做一个新的 APK：

- **MiMo 直连**：不经过 NAS / Docker / 转发网关。
- **旁白 / 对话双音色**：在 Talkify 端侧做轻量角色切分，不依赖 MultiTTS。
- **保留 Talkify 原有能力**：流式合成、Provider 配置、后台 TTS 服务、本地模型。

当前分支：`feature/role-reading`
上游 remote：`https://github.com/LonePheasantWarrior/TalkifyTTS.git`

## 已确认的上游行为

- Legado 的主朗读路径把章节按段落/行送给系统 TTS，**不是逐句**；标点保留，只有超过 `TextToSpeech.getMaxSpeechInputLength()` 才在句末标点处切。
- Talkify 的 `TextChunkSplitter` 再按 Provider 上限切：MiMo 768 字、腾讯 300 字、Azure 4096 字节。
- Talkify 当前每个请求只用一个 `config.voiceId`，`request.voiceName` 与配置不一致时只打 warning，不会切声音。
- Talkify 没有角色/NER 分析，也没有 MultiTTS 语音包导入。

## MVP 范围

只做“旁白一个、对话一个”，不做人物级 NER。

1. **输入**：整段文本（可能包含旁白 + 多句对话）。
2. **切分**：按中文/英文引号状态机切成 `NARRATOR` / `DIALOGUE` 段。
3. **选音色**：
   - 旁白用 `narratorVoiceId`
   - 引号内用 `dialogueVoiceId`
   - 同一个 Provider，先不做多 Provider 混用
4. **提示词**：
   - 把整段原文作为 context，截取当前段前后约 200–300 字
   - MiMo `user` message = 角色 + 场景 + context + 朗读要求
   - MiMo `assistant` message = 当前段文本
5. **音频**：
   - 逐段调用 Provider，`callback.start()` 只调一次
   - 同一 Provider 的 PCM 直接顺序写出
   - `onStop` 时中断循环并 `provider.stop()`

## 不做

- 不做 NER / 人物名自动识别
- 不做人物级 voice 映射
- 不做同一请求混用 MiMo + Azure/腾讯（采样率/格式不同，需要重采样）
- 不搬运 MultiTTS 的 HTTP 引擎/语音包格式

## 代码改动清单

### 1. `SynthesisParams`

文件：
`app/src/main/java/com/github/lonepheasantwarrior/talkify/service/provider/TtsProviderApi.kt`

增加可选字段：

```kotlin
val voiceIdOverride: String? = null,
val styleInstructionOverride: String? = null,
```

Provider 内部优先使用 override，为空时回退到 `config.voiceId` / `config.styleInstruction`。

### 2. `XiaomiProvider`

文件：
`app/src/main/java/com/github/lonepheasantwarrior/talkify/service/provider/impl/XiaomiProvider.kt`

- 音色：`params.voiceIdOverride ?: mimoConfig.voiceId`
- `user` message：`params.styleInstructionOverride ?: mimoConfig.styleInstruction`
- `assistant` message：当前段文本
- 保持 `stream=true`、`audio.format=pcm16`

### 3. `TalkifyTtsService`

文件：
`app/src/main/java/com/github/lonepheasantwarrior/talkify/service/TalkifyTtsService.kt`

在 `processRequestSynchronously()` 中：

```kotlin
val segments = if (roleReadingEnabled) {
    RoleSplitter.split(text, quoteStyles)
} else {
    listOf(RoleSegment(Role.NARRATOR, text))
}
```

然后逐段：

```kotlin
for (segment in segments) {
    val voice = when (segment.role) {
        Role.NARRATOR -> narratorVoiceId
        Role.DIALOGUE -> dialogueVoiceId
    }
    val prompt = RolePromptBuilder.build(
        role = segment.role,
        context = text,
        speaker = null,
        template = templateFor(segment.role)
    )
    provider.synthesize(
        text = segment.text,
        params = baseParams.copy(
            voiceIdOverride = voice,
            styleInstructionOverride = prompt
        ),
        config = config,
        listener = segmentListener
    )
    // 等待本段完成后再进入下一段
}
```

注意：

- `audioInitialized` 跨段保留，只在第一段 `callback.start()`。
- 段间检查 `isStopped` / `continuation.isActive`。
- 结束只调一次 `callback.done()`。
- 原 120 秒总超时需要改为“每段超时 + 总超时”，避免长段落误杀。

### 4. 新增 `RoleSplitter`

建议路径：
`app/src/main/java/com/github/lonepheasantwarrior/talkify/service/role/RoleSplitter.kt`

规则：

- 支持 `“”`、`「」`、`『』`、`‘’`、`""`
- 引号外 = `NARRATOR`，引号内 = `DIALOGUE`
- 去掉引号本身，保留 `，。！？；`
- 未闭合引号：剩余部分按 `NARRATOR` 处理，并记录 warning
- 嵌套引号：MVP 只处理最外层
- 纯空白/纯标点段跳过

输出：

```kotlin
data class RoleSegment(
    val role: Role,
    val text: String
)

enum class Role { NARRATOR, DIALOGUE }
```

### 5. 新增 `RolePromptBuilder`

建议路径：
`app/src/main/java/com/github/lonepheasantwarrior/talkify/service/role/RolePromptBuilder.kt`

默认模板：

旁白：

```text
你在朗读中文有声小说的旁白。
上下文：{context}
要求：用沉稳、客观、有画面感的语气；只朗读 assistant 中的当前文本，不要朗读上下文或说明。
```

对话：

```text
你在朗读中文有声小说的角色对话。
说话人：{speaker}
上下文：{context}
要求：用口语化、符合场景情绪的语气；只朗读 assistant 中的当前文本，不要朗读上下文或说明。
```

`context` 截断到约 200–300 字，避免把整章塞进去。

### 6. 配置与 UI

4. 在项目根目录创建 `local.properties`：

```properties
sdk.dir=C\:\\Users\\Administrator\\AppData\\Local\\Android\\Sdk
```

```powershell

```

